# LLM-supported Modeling Knowledge Base

This application is a small Flask web application for maintaining and exploring
a structured knowledge base about modeling approaches, modeling tasks, problems,
solutions, techniques, underlying language models, sources, and observed effects.

The application provides a browser-based interface for:

- browsing the knowledge base;
- answering built-in competency questions and displaying derived summaries;
- adding, editing, and deleting knowledge-base records; and
- maintaining relationships between related records.

## Technology

- Python 3.12 or later
- Flask 3.x
- `psycopg` for PostgreSQL-compatible database access
- Vercel Python runtime for the hosted deployment
- Supabase PostgreSQL for hosted persistence
- JSON and HTML templates for the local fallback and user interface

The Python dependencies are listed in [requirements.txt](./requirements.txt).

## Application structure

| Path | Purpose |
| --- | --- |
| `app.py` | Flask application, routes, validation, normalization, persistence, and derived queries |
| `templates/` | Jinja2 HTML templates |
| `data.json` | Local JSON persistence and fallback seed data |
| `vercel.json` | Vercel build, routing, and scheduled keep-alive configuration |
| `requirements.txt` | Python runtime dependencies |

The application is intentionally centered in a single Flask module. The home
route loads and normalizes the knowledge-base data, computes the derived
competency-question results, and renders the main page. Form routes handle
create, update, and delete operations for the different record types.

## Persistence logic

The application supports two persistence modes:

1. **Hosted mode**  
   When running on Vercel, the application uses a PostgreSQL-compatible
   connection and stores the complete data store as JSON in the
   `app_data_store` table.

2. **Local mode**  
   When running outside Vercel, the application reads from and writes to
   `data.json` by default. Remote persistence can be enabled locally with
   `ALLOW_REMOTE_PERSISTENCE`.

The database table is created automatically when the application first connects.
The database connection is expected to use TLS for non-local database hosts.

## Configuration

Set environment variables outside source control. Do not put credentials in this
README or commit local environment files.

The application accepts a PostgreSQL connection string from the first available
variable in this order:

```text
DATABASE_URL
POSTGRES_URL
POSTGRES_URL_NON_POOLING
POSTGRES_PRISMA_URL
SUPABASE_DB_URL
SUPABASE_DATABASE_URL
SUPABASE_URL
```

For local development, remote persistence is disabled unless one of the
following values is set:

```text
ALLOW_REMOTE_PERSISTENCE=1
ALLOW_REMOTE_PERSISTENCE=true
ALLOW_REMOTE_PERSISTENCE=yes
ALLOW_REMOTE_PERSISTENCE=on
```

The Vercel runtime enables remote persistence automatically. Configure the
database connection in the hosting provider's environment-variable settings,
not in Git.

## Local development

From the application directory:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python app.py
```

The local server listens on port `5000` by default. A different port can be
selected with the `PORT` environment variable:

```powershell
$env:PORT = "5001"
python app.py
```

Open `http://localhost:5000/` in a browser unless a different port was chosen.

## Deployment

The supported hosted deployment is Vercel. The configuration in
`vercel.json` sends requests to `app.py` and schedules a daily request to
`/api/keepalive` to keep the database connection path exercised.

Before deploying, configure the PostgreSQL-compatible database URL in the
hosting provider's environment settings. Never commit `.env` files, tokens,
passwords, or provider-specific project identifiers.

## Data model

The main collections in the data store are:

- solutions;
- sources;
- effects;
- underlying language models;
- model types;
- prompting techniques;
- other techniques;
- modeling tasks;
- modeling problems; and
- modeling approaches.

Records use integer identifiers and relationships are represented by identifier
fields or lists of related identifiers. `app.py` normalizes loaded records so
older data shapes can continue to be read safely.

## Operational notes

- Hosted filesystem writes are treated as ephemeral. Successful hosted saves
  therefore depend on the configured PostgreSQL-compatible database.
- Local writes update `data.json`.
- The database health endpoint is available at `/api/keepalive`.
- The debug database endpoint should only be used in a controlled development
  environment.
- Do not commit generated bytecode, virtual environments, local environment
  files, credentials, or deployment-provider metadata.
